# 工作日志周报项目汇总设计

## 背景

工作日志周视图已有“周报统计”，会过滤零人天日志，按项目合并本周工作内容，并对相同工作条目去重。当前每个项目只展示项目名称和工作内容，无法直接查看该项目本周投入的人天总数及关联禅道号。

## 目标

- 在周报统计中为每个项目分别展示本周总人天。
- 在周报统计中为每个项目分别展示本周禅道号汇总。
- 禅道号只在所属项目内去重，不提供跨项目统一汇总。
- 保持现有工作内容的过滤、排序和去重行为不变。

## 范围

本次仅修改前端周报聚合函数、周报项目卡片及相关测试。工作日志列表接口已经返回 `personDay`、`projectCode` 和 `zentaoNo`，因此不修改后端接口、数据库结构、路由或权限。

## 聚合规则

扩展 `buildWeeklyReportGroups` 的项目聚合结果，每个项目继续返回 `projectCode`、`projectText` 和 `items`，并新增：

- `personDayTotal`：该项目本周所有非零人天日志的 `personDay` 之和。
- `zentaoNos`：该项目本周所有非零人天日志中非空 `zentaoNo` 的去重列表。

聚合继续先按日志日期升序处理，因此项目顺序、工作条目顺序和禅道号顺序均以首次出现为准。单条日志中的多个禅道号按中英文逗号拆分；空字符串和纯空白禅道号不进入汇总；同一禅道号去除首尾空白后只保留一次。未关联项目仍作为独立项目组参与统计。

## 展示设计

每个周报项目卡片包含三部分：

1. 标题行显示项目名称，并在同一行展示“共 X 人天”。
2. 标题下显示禅道号汇总；有数据时使用顿号分隔，没有数据时显示“禅道：暂无”。
3. 下方继续使用现有有序列表展示去重后的工作内容。

人天沿用页面现有数值格式，避免出现无意义的小数尾零。桌面端标题行允许两端对齐；窄屏时允许自然换行，不压缩工作内容区域。

## 数据流

周视图加载本周日志后，`weeklyReportGroups` 继续调用 `buildWeeklyReportGroups`。工具函数在一次遍历中同时累计工作内容、人天和禅道号，`WorkLog.vue` 仅消费聚合结果并渲染，不在组件内重复扫描原始日志。

## 边界与错误处理

- `personDay` 缺失或不可解析时按 0 处理，并沿用现有规则排除该日志。
- `zentaoNo` 缺失、为空或仅包含空白时忽略。
- 项目没有有效禅道号时明确显示“暂无”，不隐藏该区域。
- 无有效周报日志时继续显示现有空状态。

## 测试与验收

- 工具函数测试覆盖同项目人天求和、禅道号去重、空禅道号忽略、项目间独立统计和零人天日志排除。
- 组件测试覆盖项目名称、总人天、禅道号与工作内容同时展示，以及月视图仍隐藏周报统计。
- 运行前端测试和生产构建，确认现有工作日志功能无回归。
