# 智订设计评审与框架边界

评审对象：用户提供的 `2026-11-17-ai-subs-design.md`（2026-11-17 版本）及 `3372.PNG`。
结论：产品定位和关键统计边界可作为后续开发基础；尚不能直接按实体清单开工实现完整业务。此次请求是评审并创建应用与 Logo 框架，附件中的“首期全部范围”和“本次只新增文档”均为原设计内容，不作为本次执行指令。

## 需要优先补齐的设计

1. **高：累计/增量与自动/手动的统一计量规则（§5、§6、§8）。** “同一周期覆盖快照”缺少周期 ID、时区、指标、单位、维度、来源等稳定唯一键；“官方覆盖区间排除手动”没有定义部分重叠如何裁切。建议明确观测记录与统计事实分层，首版部分重叠标为待核对并排除，禁止按天数比例猜测用量。增加重复快照、跨月区间、时区变更、官方修正与部分重叠样例。
2. **高：退款与历史摊销未闭环（§5、§8）。** 现金支出可减退款，但年费中途退订后成本如何冲回、权益结束日如何调整、历史月份是否重算尚未明确。支付需关联原支付/覆盖周期，保留不可覆盖的修正记录，并确定已封账月份政策；对部分退款、币种不同的退款与价格追溯修改给出预期值。
3. **高：同步任务状态机与密钥生命周期缺失（§6、§8）。** 唯一任务键不等于每次执行唯一，需定义失败重试、手动刷新合并、租约过期后旧 worker 写回的防护（租约令牌/版本条件更新）、最大尝试次数与覆盖进度提交事务。密钥还需规定加密主密钥来源、轮换、撤销、账号删除处理与错误信息脱敏。
4. **中：费用归属和三种金额的缺失状态需要接口契约（§4、§5、§8）。** Summary 应包含金额是否完整、原币分组、估算/确认、数据截止时间和缺失原因，不能仅返回一个总数；预算应明确约束成本还是现金支出。对未确认续费的预计成本与确认成本分别合计。
5. **中：关联范围与交付切片偏大（§7、§10）。** 密码备忘录、账单、消息、同步适配器同时进入首期会放大联调范围。建议先交付手动账号/订阅/支付的闭环，再做统一汇总与工作台，最后接入经核验的官方适配器、账单和提醒。Muse 具体产品仍待确认。
6. **中：补充删除和导出约束（§7–§9）。** 删除工具/账号/订阅时，已发生支付和用量应归档保留；取消授权后立即停止同步。导出、备份与日志均须排除可用凭据，导入后关联 ID 重映射及重新授权。

## 已经清楚且应保留的约束

- 固定套餐与开发者 API 分开；套餐内用量不重复计费，充值不当作成本。
- 消费者订阅与官方账单 API 能力分开，不宣称六家均支持自动同步。
- 月末锚定日、关闭自动续费后的权益、原币与汇率、未知值不显示为零。
- 关联密码备忘录仅保留引用，每次读取校验权限，不自动把登录密码当 API Key。

此次未联网核验各平台能力或价格，评审不构成任何厂商接口能力确认。

## 本次框架

- 应用编码 `APP_AI_SUBSCRIPTION`，路由 `/ai-subscriptions`，名称「智订」，分类「效率工具」。
- 使用原始透明 PNG，不重绘、不替换颜色；图标解析关闭旧 PNG 的品红抠色逻辑。
- 复用应用目录、应用坞、搜索和权限读取；四个分区可切换，无演示金额、假保存或假同步。
- 数据库仅新增应用目录及默认管理员授权，不创建业务表；已有授权/撤权和自定义应用配置不会被脚本覆盖。
- 独立首页统计卡片、后端业务模块、API wrapper 和快速新增随真实接口交付；当前无对应可提交业务表单，因此不增加三个空快捷入口。
- 未修改用户原始设计文档；未提交 Git。
