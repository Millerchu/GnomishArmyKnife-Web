# 应用布局开发规范

从工作台打开应用后，用户应能在同一位置找到返回入口、识别当前应用，并直接开始主要任务。普通应用以 [智订](../src/views/AiSubscriptions.vue) 的页头、视图导航和主题用法为参考。其配额面板属于订阅业务，各应用按自身任务组织正文。

## 新增与改版要求

1. 页头左侧提供返回工作台入口，图标按钮的可访问名称统一为“返回工作台”。紧邻返回入口显示唯一的页面主标题。需要主题切换时在右侧复用 ThemeToggle。业务说明放到对应功能附近。
2. 多视图应用在标题下设置视图导航，标明当前项。单视图直接进入正文。筛选条件紧邻受影响的结果，新建、编辑等操作靠近其作用的列表或记录。首屏优先露出可操作的业务内容。
3. 普通数据页默认采用居中容器，参考智订的最大宽度 1360px、水平内边距 clamp(16px, 4vw, 40px)。页头、筛选和正文对齐同一条左边线。计算器、画布和乐器可以按操作面所需宽度排布。
4. 正文、辅助文字、表面和边框分别复用 --theme-text、--theme-text-muted、--theme-surface、--theme-border。业务色用于图表和状态，同时提供文字或图形标识。优先沿用 MacDialog、MacEmptyState 等已有组件。
5. 窄屏允许页头操作和筛选换行，多列内容收为单列。宽表在表格区域滚动，视图导航可局部横滑。保留返回、主标题和主要操作，键盘操作时焦点可见。
6. 交付前在桌面和手机宽度各打开一次真实入口，检查浅色与深色、长标题、空数据和加载失败。验收记录写明所测页面与尺寸，确认首屏可辨认任务、页面无意外横向滚动、弹窗关闭后可继续原操作。

## 存量应用调整顺序

以下为 2026-11-24 根据路由页面模板与样式所做的静态审查。优先级按结构差异和可批量复用程度排列，实际留白和折行需在改版时用浏览器复核。

| 顺序 | 应用 | 实现差异与调整建议 |
| --- | --- | --- |
| 第一批 | 应用管理、用户管理、权限管理、数据字典、数据迁移 | 均以 page-nav 后接 hero-panel 开场。先用应用管理验证紧凑页头，再推广到同组。筛选、迁移步骤和权限操作各自留在业务区域。 |
| 第一批 | 待办列表、计算器、软件仓库、经验库、健康、WoW角色统计、芽记 | 同样把返回与标题拆成两个区块。合并页头，把空间还给待办、键盘、检索或记录。芽记也是这一结构，不能仅按开发时间判断。 |
| 第二批 | 工作日志、油耗统计 | 导航内另设移动端标题。统一标题与返回位置，优先验证手机端，保留面向填写日志和查看统计的快捷操作。 |
| 第二批 | 密码备忘录、个人账单、行笺 | 分别采用 memo-page-header、topbar 加 month-hero、topbar 加 hero。统一入口和标题层级，保留账单月份及行程上下文。 |
| 第二批 | 消息中心、消息管理、系统日志 | 消息两页共用 messages-nav，适合成对调整。系统日志将返回链接独占一行，可并入标题栏，保留手动刷新及筛选表单。 |
| 参考或专项验收 | 智订、随身乐器、星空交互页 | 智订作为普通数据页基准。乐器的操作面和星空画布各有空间需求，只对齐返回、焦点与主题可读性。 |

工作台是应用入口，登录和注册是认证流程，分别按各自流程评审。
